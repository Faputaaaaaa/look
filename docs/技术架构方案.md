## 0. 项目意图与边界

目标不是套用一个现成的 YOLO/Anomalib 应用，而是**围绕自研缺陷检测器形成可解释、可复现、能通过消融实验论证的算法体系**：

1. **近期主目标**：同一瓶身出现 `missing`、`dirty` 等多种缺陷时，能够在一张图／视频的一帧中同时定位多个缺陷实例、输出各自类别与置信度；首先保证可靠的召回和误检控制。
2. **近期第二目标**：把目前按原图串行 SAHI 检测约 21–25 秒/图的链路逐步改为可持续处理相机视频帧的在线系统。*“实时”应通过相机帧率、允许端到端时延和硬件资源定义，而不能仅以窗口推理耗时代表。*
3. **中长期主目标**：学习丝印缺陷本身的局部外观和形态，尽可能减弱对瓶型、Logo、印刷排版、颜色、光照的依赖，让某种瓶型上学到的缺陷在未见过的瓶型上仍可迁移。
4. **研究边界**：保留自研主干、FPN、检测头和数据/评测主导权；可研究、复现、组合开源思想或获许可的组件，但核心系统不是简单外包给完整检测框架。

必须分清：

- **同图多个不同位置的缺陷**：标准多类别多实例检测即可表达；每个 ROI 输出一个类别通常足够。
- **同一块位置同时存在两种缺陷标签**：可能需要多标签 sigmoid 分类头或像素级多类/多标签分割；不能把取消 Top-1 误认为已经实现这个能力。
- **未知瓶型的已知缺陷**：跨域/跨对象泛化；并不等价于**未知缺陷类别**的开放集识别。后者需要异常区域分支，并且其输出通常是“异常/未知”，不保证可以命名缺陷类型。

## 1. 经源码核验的当前事实

| 位置 | 实际实现 | 风险 / 结论 |
|---|---|---|
| `model_fpn.py` | ResNet18 + FPN(P2/P3/P4) + RPN + ROI Head，自研两阶段模型，ROI 类别为背景 + 前景 Softmax | 有基本的多类别实例能力，但在推理和训练数据上受约束；不是必须推倒重来 |
| `model_fpn.py:788–790` | ROI 阶段执行 `nms(final_boxes, final_scores, ...)`，与类别无关 | 两个不同类别的重叠框可能被错误互相抑制 |
| `sahi_inference.py:145–275` | 整图 640×640 窗口、步幅 320、逐窗口串行推理，最终按置信度 `[:keep_k]` | 浪费重复边界窗口；原图 Top-K 默认只有 1 个 |
| `config.py` | `max_dets_per_image=1`，支持用户调高；`INFERENCE_CONFIG['max_detections']=5` 为单切片上限 | UI Top-3/5 并不代表模型受过多缺陷训练；仅开放多个候选输出 |
| `sahi_inference.py:225–226` | 遍历类别时检测到结果数 `>= MAX_DET*2` 就提前停止 | 类别遍历顺序可能导致后续类别结果被丢弃 |
| `dataset.py:258–302` | YOLO 标签可逐行读入多框，`max_objects=10` | 输入标签形式已具备多对象基础，但数据实际单缺陷，且对象超限会静默截断 |
| `dataset.py:335–390` | 裁窗标签仅在 **GT 中心落入窗口** 时保留 | 边界跨窗且中心在窗外的缺陷可能被当作背景；跨窗正样本一致性仍须专门处理 |
| `dataset.py:101–193` | 滑窗训练保留所有正窗，每图随机抽 2 个负窗 | 适合单缺陷起步；复合样本下应按缺陷实例、窗口难度和负例密度重新设计采样 |
| `train.py:825–866` | ROI 正例为零时，选最高 IoU 5 个 proposal **直接作为正例保底** | 在全部 proposal 都很差时存在错误正标签梯度风险；应做 IoU 下限消融 |
| `train.py:754–785` | 纯背景窗口参与 RPN 负样本，跳过 ROI Head | 背景的 ROI 分类训练不足，应试验加入硬负 ROI，但需对照防止类别失衡 |
| `sahi_inference.py:42` 及平台适配器 | 部分类名映射写死 `missing/dirty` | 扩展为原始标注支持的 7 类时，映射应由统一配置派生 |
| `defect_platform/` | PyQt5 图片检测平台，QThread 后台推理，已提供 `detect_bgr()` 内存输入 | **不是实时摄像头系统**，但适配器可作为相机接入起点 |
| `STATUS.md` / `HANDOFF.md` | 20 epoch：mAP@0.5=0.7788，missing AP=0.917，dirty AP=0.640；单图 SAHI 21–25s | 历史基线，不是本次跑分 |
| `_check_dirty_labels.py` / `HANDOFF.md` | dirty 标注存在固定尺寸框、贴放位置差异，建议人工复核约 24 张 | 优先校正标注，否则单纯调网络难以稳定提升定位 AP |
| `split.json` | 按原图划分训练/验证，避免切片级泄漏 | 做当前瓶型内部评估基本必要，但**不能**证明跨瓶型泛化；相邻视频帧还应按采集组隔离 |

### 特别提醒

仓库内 `STATUS.md` 记录的数据集每类约 100 张、每张 1 个缺陷、原图 4096×2736；其中 only `missing` 与 `dirty` 被用于现有模型。`config.py` 的 YOLO 原始类别表另包含 `ghosting`、`faint`、`fuzziness`、`scratch`、`body_scratch`，**不代表这五类已有足够数据可直接训练**。

现有 0.7788 mAP 是“单缺陷、同分布、Top-1”基线。改变 Top-K / NMS / 标签定义后**不能直接和历史结果宣称公平对比**；需要并行保留 legacy 评估配置。

## 2. 最优先的实际改动：PR1（已附可应用补丁）

**文件**：`look-pr1-multidefect-inference.patch`（本交付同时提供）。

1. 在 `model_fpn.py` 将 ROI 的类别无关 NMS 改为 `batched_nms` 的按类别 NMS；保留 RPN 的类别无关 NMS（RPN 天然是 class-agnostic）。

**安全性与基线策略**：不改变 `config.max_dets_per_image=1`，这样旧评估配置不被悄然改写。要尝试一图多缺陷，请在平台中选择 Top-3/5，或在调用适配器时显式传 `max_dets=10`。这**仅开放多检测输出**，并不解决模型是否学会共存缺陷的问题。

## 3. PR2：数据/评估基础必须先升级

### 3.1 标注整理

- 首先复核 `_check_dirty_labels.py` 标出的 dirty 可疑框，不预设算法框一定正确。
- 建立统一标注 schema：`image_id`、`bottle_sku`、`print_design_id`、`production_batch`、`camera_id`、`capture_session`、`defect_instances[{class_id, bbox, optional mask}]`、`annotator`、`review_status`。
- 必须允许 0 / 1 / N 个缺陷共存；同一个缺陷实例有唯一 ID，完整框和被窗口裁切的片段框不能混为独立缺陷。
- 增加双人复核、争议样本集（尤其 ghosting/faint、dirty/scratch 等易混类）；对低对比度/模糊边界标注给出统一规则。
- 当前仅 bbox 足够进行 P0 多实例实验。中期对丝印断笔、脏点、拖影优先补局部 mask（至少保留小批精确像素标注供异常分割头评测）。
- 标签缺失的样本不得无条件当作纯正常样本；异常教师分支尤其要求高质量正常图。
- `max_objects` 不允许静默截断：按模型支持范围明确报错或使用动态目标列表。

### 3.2 三层数据集

| 集合 | 目的 | 典型划分 |
|---|---|---|
| A：现有同瓶型 | 公平复现、验证对旧场景无回归 | 按物理瓶/采集 session 隔离；修复现有原图 split 潜在邻帧泄漏 |
| B：真实多缺陷 | 验证多类别、多实例同图识别 | 所有共存组合单独报告；不能只用合成图验证 |
| C：未见瓶型 | 验证目标泛化能力 | 训练不出现的瓶型/SKU/印刷图案**整组留出**，最终测试前冻结阈值、方法和超参数 |

- 所有合成增强和同源切片先按原始采集组切分，再仅在 train 生成，严禁 train/val 同源变体泄漏。
- 如果 C 集里的瓶型参与阈值选择、预训练特定参照样本收集或正常模板建设，须明确标为 *few-shot adaptation*，不能再叫严格的 zero-shot / unseen-SKU。
- 建议保留独立小型“上市前验收集”：每个 SKU 包含正常、单缺陷、复合缺陷、光照/角度变化和混淆负例。

### 3.3 评测指标

第一主指标不能只有 mAP：
- **定位与分类**：mAP@0.5、AP@0.75、逐类 AP/P/R、各类别混淆矩阵；评估同一实例被重复检测。
- **多缺陷完整性**：每图真实缺陷数、预测数、全检率（all-defects-found）、每实例 recall、每图误检数、复合类别召回率。
- **产线成本**：固定误拒率/每百正常瓶误报量下的缺陷召回；正常瓶通过率与漏检率单独报告。
- **跨瓶型能力**：已见 SKU vs 未见 SKU 的指标差值，按 SKU 与缺陷类别交叉汇总，避免平均值掩盖失效类。
- **实时性**：p50/p95 端到端延迟、GPU/CPU 占用、有效检测吞吐（处理帧数/秒）、丢帧率、采集到显示延迟；固定 RTX 4060 Laptop TGP、分辨率、设备、batch、FP16 设置。
- 统一置信度阈值的选择依据，阈值仅在 validation/校准集确定，禁止针对 test 逐图调参。

**PR2 文件建议**：`data_manifest.py`、`tools/audit_labels.py`、`tools/build_group_split.py`、`evaluation/metrics.py`、`tests/test_split_leakage.py`、`tests/test_multi_gt_matching.py`、`docs/DATA_CONTRACT.md`。

## 4. PR3：从“单缺陷样本”升级为“多缺陷共存训练”

这是最直接决定近期识别率的模型改造。必须在真实多缺陷测试集上比较。

**路线 A（优先，最小改动）**：保留 TwoStageDetector/ROI Softmax；用真实多实例标签训练，取消训练样本中“每图只一个目标”的假设。改正正负 proposal 匹配、同类/异类重叠处理、窗口 GT 裁切，增加 ROI 负样本训练。此时不同区域各有各的类别，已经能输出多个缺陷，不必先改成 sigmoid 多标签。

**路线 B（数据较少时的补充）**：针对每类缺陷制作质量受控的实例级 Copy-Paste 合成：
- 将 missing/dirty 等缺陷局部 patch 或像素 mask，融合到**丝印内容有意义的位置**；采用泊松融合或颜色光照匹配时要防止掩盖真实缺陷边界。
- 在同一正常瓶上生成 2–4 个缺陷实例；组合远距、相邻、接近重叠，并同步更新所有 bbox / mask。
- 对光源方向、反光、材质、曲率、文字位置做现实约束；合成图像不代替真实复合缺陷验证。
- 对比**真实多缺陷训练**、**真实+Copy-Paste**和**真实+随机噪声增强**，只保留有真实测试收益的策略。
- 对缺陷位置受工艺限制的类别，绝不能复制到物理上不可能发生的区域。

**路线 C（按需）**：如果一块区域确实应有 `missing` 与 `dirty` 两种标签，另设 multi-label classification head（K 个 sigmoid + class-wise BCE）并把相应 GT 匹配策略改变；不要直接将现有 Softmax 换 sigmoid 而不改标签和损失。

### 重点实验

1. 单缺陷真实 train → 多缺陷真实 test（基线）。
2. 单缺陷 + 合成复合 train → 多缺陷真实 test（量化增益）。
3. 添加少量真实多缺陷 train → 多缺陷真实 test。
4. 分别检查 `roi` 无正样本时“最高 IoU 强行保底”为真阳性导致的错梯度，添加最小 IoU 门槛或 GT box injection 的对照实验；务必量化 RPN/ROI recall，而不是拍脑袋改阈值。
5. 保持同组的旧验证集评测，以判断是否发生 catastrophic forgetting。

**PR3 文件建议**：`dataset.py`、`train.py`、`model_fpn.py`、`augmentation/multi_defect_copy_paste.py`、`tests/test_multi_instance_training.py`、`docs/EXPERIMENTS.md`。**该 PR 必须真实训练后方可声称提升准确率。**

## 5. PR4：让相机视频的在线推理可行

当前 4096×2736 的 117 次串行前向（边缘重复去除后 96 次）远非视频实时处理；单纯开 Qt 工作线程只是“不冻结 UI”，不等于实时。

建议按照 profiler 实测的吞吐瓶颈逐级实施：

**阶段 1：低风险推理优化**
- 缓存 anchors / feature map 常量（`model_fpn.py` 的 anchor 生成与网格循环）。
- 把 `preprocess_crop` 改为批量生成/批量归一化，尝试 micro-batch=2/4/8；保持输入顺序和坐标映射，避免 CPU、GPU 频繁同步。
- 对 `extract_rpn_proposals` 中的 64 个 cell 逐 cell NMS、ROI 的逐 proposal Python 操作做 profile，优先减少 Python launch 与候选数。
- 尝试 `torch.inference_mode()`、CUDA autocast FP16，检查是否有 box 解码溢出或高置信度误检；**仅速度实验不能忽略精度回归**。
- 分开统计解码/预处理、GPU 前向、proposal、ROI、NMS、绘图，CUDA 测时需要 synchronize。

**阶段 2：改变全图扫描代价**
- 先检测瓶身/丝印区域 ROI，必要时做圆柱面展开或几何配准，然后**只在有效印刷区域**进行多尺度检测；
- 在高质量定位的前提下测试 50% → 25% overlap / coarse-to-fine 策略，重点验边缘小缺陷漏检；
- 通过“低分辨率全局粗检 + 可疑区域高分辨率精检”替代固定遍历整个 4096×2736 图的 96 个窗口；
- 评估图案先验方法的跨瓶型失败风险（不同瓶型需模板适配，不可把模板相关性当作泛化能力）。

**阶段 3：架构优化**
- 基于自研 ResNet18-FPN 实现轻量 dense detection head（可参考 FCOS/anchor-free 设计）以替代高成本 RPN+ROI Align 的推理路径，先做单任务检测精度–速度 Pareto 对比，再考虑融合异常分支；
- 保留现有 TwoStageDetector 做 teacher / 精度对照；如果轻量分支效果更好再迁移到线上，而不是一次性推翻研究资产；
- 视频采集线程和推理线程解耦，队列有限长（如 1–2 帧），后到优先，记录丢帧；按物理瓶 ID 聚合多帧结果，避免一个瓶子的不同帧误认为多个样本；
- 研发阶段可设置候选工程验收目标，例如 p95 端到端 < 200ms/帧；*该阈值并非现有系统已达成，最终必须由相机、传送带速度与产线精度共同确定。*

**PR4 文件建议**：`sahi_inference.py`、`model_fpn.py`、`inference_utils.py`、`defect_platform/camera_worker.py`、`benchmarks/latency_profile.py`、`docs/REALTIME_PROTOCOL.md`。引入视频入口后，所有评估/平台仍共用同一个核心推理函数，不能发展出两个含不同阈值的“真相来源”。

## 6. PR5：形成具有研究价值的跨瓶型泛化结构

### 推荐最终架构：PrintDefectNet（建议名称，非已有论文或已实现模型）

```text
工业相机帧
  ↓
瓶身/丝印区域提取 → 形变/旋转/尺度对齐（可选）
  ↓
自研轻量 Backbone + P2/P3/P4 FPN
  ├─ A：监督式多实例缺陷检测头
  │     └─ 预测 known class + bbox / optional mask
  └─ B：局部视觉异常 head
        └─ 正常纹理特征蒸馏 / teacher-student distance
                ↓
  置信度校准 + 多分支定位融合 + unknown/anomaly 标志
                ↓
  单瓶多缺陷结构化列表、ROI 热力图、置信度与审计记录
```

**最优先的“创新”建议**：**丝印 ROI 几何归一化 + 对象无关缺陷局部特征 + 监督检测 / 异常残差双任务融合**。这个组合具备明确工业动机，也可以做 4 组消融：
- 自研检测器 alone。
- 检测器 + 几何归一化。
- 检测器 + 轻量异常分支。
- 检测器 + 几何归一化 + 异常分支。

**但要先验证一个反例**：新瓶型的新图案/字形本来就是正常差异，完全没见过的新设计可能被异常分支大量报警。为此：
1. 让异常分支尽量学习局部结构破坏、印刷边缘连续性、颜色和纹理一致性，而不是记住一张旧瓶的整体图案。
2. 如果能获取当前 SKU 的正常样本或正版丝印模板，提供**显式的有参照模式**，并把它与严格无参照零样本检测分别计分。
3. 允许检测器识别“类别可信”，但异常分支只输出“未知异常/需要人工复核”，而不是强制把所有异样都分配到 missing/dirty。
4. 大型 DINOv2/DINOv3 teacher 用于**离线蒸馏和泛化对照**；在线以轻量 student 为主，不能把大 teacher 在每个 640×640 切片运行 96 次，否则违背实时目标。
5. 训练同时施加局部实例特征对比学习/域随机化，以减少对瓶身颜色/整体 Logo 的依赖，但不能消除真实的 OOD 边界。

### 量化里程碑（建议验收目标，尚非已达到指标）

- 第一阶段：新多缺陷真实测试集上保证**能同时输出两种及以上缺陷类别**，并报告每类实例召回；不强制立即实现 7 类。
- 第二阶段：以当前 0.7788 mAP@0.5（旧测试口径）为底线尽量提升，尤其关注 dirty AP=0.640 的标注瓶颈；多缺陷集另建新基线。
- 第三阶段：在真实 RTX 4060 Laptop + 指定工业相机配置下，对吞吐率做 Pareto 对比；可先争取 5 FPS，再根据产线需要考虑 10 FPS 或更高，**这是工程目标，不是性能承诺**。
- 第四阶段：跨 SKU held-out 评测应同时展示缺陷检出率与正常瓶误报率；不能通过给新瓶型测试集反复调阈值“刷出泛化”。

## 8. 需要你未来补充的关键材料（不阻碍当前 PR1）

1. **原始数据与模型**：能否提供少量脱敏图（含 GT：正常、单 missing、单 dirty、双缺陷共存）以及 `best_model.pth`？现仓库未提供，可应用的补丁不能代替真实检测实验。
2. **定义多缺陷**：是否仅需要同一个瓶不同位置的不同缺陷；还是同一个局部区域也必须同时挂两种或更多标签？这是 Softmax 检测与 multi-label 分割的架构分界。
3. **实时边界**：工业相机还是 USB 相机？图像大小、帧率、传送带每秒经过瓶数？目前项目记录为 4060 Laptop，是否保持不变？
4. **泛化定义**：未知瓶型能否在上产线前提供该 SKU 的少量合格瓶或设计模板？若可以，这是 *few-shot/template-conditioned* 模式；若绝对不允许，才是更困难的 *zero-shot unseen-SKU* 模式。
